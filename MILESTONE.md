## Phase 2 — Looms and production

API:

- [x] Looms: add, edit, status, place; number unique per factory
- [x] Saree jobs: one or two weavers, wage or rate per inch, length (216 default)
- [x] Wage and rate are copied onto the job, so editing a template later cannot
      rewrite what a weaver already earned
- [x] Weekly inch entry, filed against the Monday of its week
- [x] One entry per saree per week, so two weavers on one loom cannot file the
      same inches twice
- [x] Refuses more inches than the saree has left, unless confirmed
- [x] `trusted` flag: auto-approve, otherwise the owner's queue (where the
      number can be corrected before approving)
- [x] Progress counts approved entries only
- [x] "Saree finished" and "Shift worker" (inches ÷ length × wage)
- [ ] Saree types (model exists, no routes yet — a job works without one)
- [ ] Weekly and monthly reports

Web:

- [x] Loom list with progress bars
- [x] Add loom, start saree, finish saree
- [x] Weekly inch entry on the weaver's phone, with the overflow confirmation
- [x] Owner approval queue: approve, correct the number, or reject
- [ ] Shift weaver (API done, no screen yet)

## Phase 3 — Offline (PWA install not yet verified on a device)

- [x] Dexie outbox for entries filed with no signal
- [x] Client-generated UUID per entry; the server returns the entry it already
      has instead of filing the week twice
- [x] "Saved on this phone, waiting to send" banner, and failed entries shown
      with the reason and a way to discard them
- [x] Auto-send on the `online` event, on mount, and on a 30s timer
- [x] Last-known-good cache for `/api/me` and the weaver's sarees, so reopening
      the app with no signal does not look like being signed out
- [x] Payments stay online-only: nothing but production entries uses the outbox
- [x] Manifest, icons (generated by `pnpm -F @loom/web icons`) and a service
      worker in the build: 9 precached entries
- [ ] **Service worker not verified.** Registration fails in the in-app browser
      pane ("unknown error occurred when fetching the script") in both dev and
      a production build, so install and offline-app-shell need checking on a
      real phone or desktop Chrome. Offline entry itself does not depend on it
      and is verified: the API was stopped, an entry filed, the app reloaded,
      and the entry sent itself once the API came back.
- [ ] Dev service worker left disabled; see the note in `vite.config.ts`
